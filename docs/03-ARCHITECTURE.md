# 03 — Technical Architecture

## 1. Overview
```
Browser ──► Vercel (Next.js App Router)
              ├─ (frontend) route group: marketing pages, RSC, ISR + cache tags
              ├─ (payload) route group: /admin + /api (Payload 3, same app)
              ├─ Server Actions: quote submit
              └─ next/og: OG images
Payload ──► Supabase Postgres (db-postgres adapter, pooled connection)
Payload ──► Supabase Storage (S3-compatible storage adapter) for media
Server   ──► Resend (email) · Cloudflare Turnstile (verify) · Plausible (events)
```
Why Payload: TypeScript-native schemas, runs inside the Next app (no separate CMS server), Postgres fits the existing stack, no per-seat SaaS pricing, full data ownership, and it doubles as a studio showcase. Trade-off: we own patching. Subscribe to Payload security advisories and keep it on the latest minor.

## 3. Collections (Payload)

### `posts`
| Field | Type | Notes |
|---|---|---|
| title | text, required | ≤ 90 chars |
| slug | text, unique, required | auto from title, editable |
| excerpt | textarea, required | ≤ 180 chars |
| coverImage | upload → media | optional; OG falls back to generated |
| content | richText (Lexical) | blocks enabled: Code, Callout, ImageCaption, Video, Table, CTA, CaseStudyRef |
| topics | relationship → topics, hasMany | min 1 |
| featured | checkbox | one featured shown on index |
| relatedCaseStudies | relationship → case-studies | optional |
| publishedAt | date | scheduling |
| seo | group: metaTitle, metaDescription, canonical, noindex | |
| readingTime | number, hidden | computed in `beforeChange` |
Versions + drafts enabled (`versions: { drafts: { autosave: true, schedulePublish: true } }`). Live preview URL → `/api/draft?collection=posts&slug=…`.

### `topics`
title, slug, description.

### `case-studies`
title, slug, summary (≤160), industry (select), services (relationship → services, hasMany), timeline (text), stack (array of {name, icon}), coverMedia (upload; image or video + poster), demoUrl, repoUrl, atAGlance (group: problem, solution, result), problem (richText), featureShots (array of {media, caption ≤ 240}), architecture (upload SVG or code field for Mermaid), results (array of {value, label, note}) — optional, order (number), showOnHome (checkbox). Drafts enabled.

### `services`
title, slug, outcomeLine (≤ 80), summary, heroVisualKey (select mapping to a component in `components/visuals`), sections (blocks), faqs (relationship → faqs), relatedCaseStudies.

### `faqs`
question, answer (richText), category (select: process, ownership, communication, payments, support), showOnHome, order.

### `media`
upload with `alt` **required** (validate non-empty), caption; image sizes generated; accepted mime: image/*, video/mp4, video/webm, image/svg+xml (sanitize SVG on upload).

### `quote-requests` (admin-only read; no public read access)
projectType (select), timeline (select), stage (select), name, email, company, description, source, status (select: new, contacted, call-booked, quoted, won, lost — default new), notes (textarea, internal), meta (group: utm_source/medium/campaign, landingPage, referrer, userAgent hash, country from `x-vercel-ip-country`), createdAt.
Access: `create` only via server action using Local API with `overrideAccess`; `read/update/delete` for authenticated admins only.

### `users`
Payload auth; admins only. Enforce strong passwords; enable 2FA plugin if available at build time; restrict `/admin` login attempts (Payload `maxLoginAttempts: 5`, `lockTime: 15min`).

## 4. Rendering, caching and revalidation
- Marketing pages: static with ISR. CMS fetchers use `unstable_cache`/`"use cache"` (whichever the installed Next version supports) with tags: `posts`, `post:${slug}`, `case-studies`, `case-study:${slug}`, `services`, `faqs`, `home`.
- Payload `afterChange` / `afterDelete` hooks on each collection call `revalidateTag()` for the list tag + item tag (and `home` when `showOnHome`/featured changes).
- `generateStaticParams` for posts, case studies, services, topics.
- Draft mode: `/api/draft` validates a secret + user session, enables `draftMode()`, redirects to page; fetchers pass `draft: true` when enabled.

## 5. Quote pipeline
1. Client wizard (`components/quote`) holds state; validates each step with the shared Zod schema slice.
2. Step 3 submit → Server Action `submitQuote(formData)`:
   - Verify Turnstile token server-side; reject honeypot-filled submissions silently (return success UI, don't store).
   - Rate limit: 5 per IP per hour (Upstash Redis or Postgres-backed counter table; choose Postgres if avoiding a new service).
   - Full Zod parse; normalize email; strip HTML from description.
   - `payload.create({ collection: 'quote-requests', ... })`.
   - Send two emails via Resend (React Email): internal notification (all fields + admin link) and requester confirmation (what happens next, reply-to studio inbox).
   - Email failures must not lose the lead: store first, send after, log failures, show success.
   - Return `{ ok: true }` → client routes to `/quote/thanks?type=…`; fire `quote_submit`.
3. Errors: field-level messages; network error banner "We couldn't send your request. Check your connection and try again." — form data preserved.

## 6. SEO
- `generateMetadata` per route from `lib/seo.ts`; title template `%s — Zyntrivia`.
- JSON-LD: `Organization` (site-wide), `WebSite`, `Article` (posts), `CreativeWork` (case studies), `Service` (service pages), `FAQPage` (FAQ sections), `BreadcrumbList`.
- OG images: `next/og` template — `--bg` canvas, title in Bricolage Grotesque, small Flow Canvas motif, logo.
- `sitemap.ts` built from CMS (published only); `robots.ts` disallows `/admin`, `/api`, `/quote/thanks`.
- Canonicals; trailing slash policy consistent; redirects map from v1 URLs in `next.config` (`redirects()`) — collect v1 routes before launch.
- RSS 2.0 at `/rss.xml` (latest 20 posts, full excerpt).

## 7. Analytics (Plausible, cookieless — no consent banner needed for analytics; confirm with privacy policy)
Wrapper `track(event, props)` in `lib/analytics.ts`, no-op in dev.

| Event | Props | Fired when |
|---|---|---|
| `cta_click` | `location` (hero, nav, sticky_mobile, services, work, final, blog_inline, blog_end, case_study), `label` | Any "Request a quote" click |
| `secondary_cta_click` | `location`, `label` | "See our work" etc. |
| `quote_step_view` | `step`, `type` | Each wizard step shown |
| `quote_step_complete` | `step`, `type` | Next pressed with valid step |
| `quote_submit` | `type`, `timeline` | Successful submit |
| `quote_error` | `kind` (validation, turnstile, rate_limit, server) | Failure |
| `case_study_view` | `slug` | Case study page view |
| `demo_open` | `slug` | "Open live demo" click |
| `repo_open` | `slug` | "View code" click |
| `blog_read_75` | `slug` | 75% scroll depth on post |
| `faq_open` | `question_id` | Accordion expanded |
Set up a Plausible funnel: `/` → `quote_step_view(1)` → `quote_step_view(3)` → `quote_submit`. Preserve UTM params into quote meta.

## 8. Performance budgets
| Budget | Limit |
|---|---|
| Homepage first-load JS (gzip) | ≤ 160 KB |
| Hero LCP element | Headline text (not canvas, not image) |
| Fonts | 2 families preloaded max; variable fonts; `size-adjust` fallbacks via next/font |
| Video loops | ≤ 1.5 MB each, lazy, `preload="none"`, poster ≤ 60 KB |
| Images | `next/image`, AVIF/WebP, explicit sizes |
| Third-party scripts | Plausible (defer) + Turnstile on `/quote` and final CTA only |
Motion/canvas islands load with `dynamic()` after hydration of static hero text; below-fold visuals use `IntersectionObserver` to mount.

## 9. Security & privacy
- Env vars (`.env.example`): `DATABASE_URL`, `PAYLOAD_SECRET`, `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_REGION`, `RESEND_API_KEY`, `QUOTE_NOTIFY_TO`, `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY`, `NEXT_PUBLIC_SITE_URL`, `DRAFT_SECRET`, `PLAUSIBLE_DOMAIN`.
- Security headers in `next.config`: CSP (allow Plausible, Turnstile, Supabase storage host), `X-Content-Type-Options`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`.
- GDPR (EU clients): privacy policy covers quote data, retention (delete `lost` requests after 12 months — scheduled job or manual admin task), processor list (Vercel, Supabase, Resend, Cloudflare, Plausible). Choose Supabase EU region if most leads are EU; otherwise US and disclose.
- Payload: keep on latest patch; never expose `quote-requests` via public API; disable GraphQL playground in production.
